# BurgerAPI — LLM Reference (condensed)

BurgerAPI is a Bun-native API framework. Routes are defined as files under an API directory; each `route.ts` exports HTTP-method handlers like `GET(req: BurgerRequest)`. Version: 0.11.0.

## Install
```
bun add burger-api
```

## Hello world
```ts
// api/hello/route.ts
import type { BurgerRequest } from "burger-api";

export async function GET(req: BurgerRequest) {
  return Response.json({ message: "Hello world" });
}
```

## Start the server
```ts
import { Burger } from "burger-api";
const burger = new Burger({ apiDir: "api" });
burger.serve(4000);
```

## BurgerRequest
Extends the standard `Request` with:
- `req.params: Record<string, string> | undefined` — dynamic path params (`[id]`).
- `req.query: Record<string, string | string[]> | undefined` — parsed query string, evaluated lazily.
- `req.route: { path: string; pattern: string } | undefined` — matched route; present on every matched route including static routes.
- `req.validated: { params?; query?; body? }` — data validated by Zod schemas.
- `req.set: { status?: number; headers?: Record<string, string> | Headers } | undefined` — response mutation applied at pipeline exit.
- `req.wildcardParams: string[] | undefined` — catch-all segments (`[...slug]`).
Plus standard `Request` members: `method`, `url`, `headers`, `signal`, `body`, `bodyUsed`, `json()`, `text()`, `arrayBuffer()`, `blob()`, `formData()`, `clone()`.

Prefer `req.query` over `new URL(req.url)` (lazy, no `URL` allocation).

## Validation
Export a `schema` with Zod per method:
```ts
export const schema = {
  get: { query: z.object({ limit: z.coerce.number().optional() }) },
};
```
Validated data is available on `req.validated.query` / `.params` / `.body`.

## Middleware
Middleware receives `BurgerRequest` and returns:
- `Response` — short-circuit the chain.
- `function (response) => Response` — transform the final response (runs after the handler).
- `undefined` — continue to the next step.
Attach via an exported `middleware` array per route, or the `globalMiddleware` option.

## Response mutation
```ts
req.set = { status: 201, headers: { "x-total": "42" } };
```
Applied once at the end of the pipeline by `applySet`; no-op (returns the original `Response`) when empty. Also runs on auto-`HEAD`.

## Routing
- Static: `api/health/route.ts` → `GET /api/health`
- Dynamic: `api/users/[id]/route.ts` → `GET /api/users/:id`, read via `req.params.id`
- Wildcard: `api/files/[...]/route.ts` → `GET /api/files/*`, read via `req.wildcardParams`
- Route groups: `(admin)/...` folders do not affect the URL path.

## OpenAPI
OpenAPI 3.0 is generated from routes and Zod schemas; Swagger UI is served automatically.
