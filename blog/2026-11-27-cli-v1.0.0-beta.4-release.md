**`@burger-api/cli` 1.0.0-beta.4 and `@burger-api/node-server` 0.1.2 are out. `doctor` now finds auth plugins that still need the security update, and body-size-limiter works on Node for requests without a body. `burger-api` stays at 1.0.0-beta.2.**

{/* truncate */}

## Update

```bash
bun add -g @burger-api/cli@latest
bun add @burger-api/node-server@latest   # only if you deploy to Node
```

Installed the CLI with the install script? Run the script again.

Then check your project:

```bash
burger-api doctor
```

## `doctor` checks copied hooks and plugins

`burger-api add` copies hooks and plugins into `ecosystem/`, so updating the CLI does not update them. The [1.0.0-beta.2 release](/blog/burger-api-v1.0.0-beta.2-release) fixed the auth plugins, but a copy made before it still checks credentials after validation.

`doctor` now finds those copies and fails with the command that fixes them:

```bash
burger-api add jwt-auth --force
```

Other official hooks and plugins that are out of date get a warning. Your own hooks and plugins are not checked. Because `doctor` exits `1` on an old auth plugin, a CI step that runs `doctor` will fail until you update it. See [Doctor Command](/docs/cli/doctor#copied-hooks-and-plugins).

Every official hook and plugin now ships a `package.json` with its version. The auth plugins are at `0.2.0`.

## Node: requests without a body

With node-server 0.1.1, a POST, PUT or DELETE sent without a body (for example `curl -X POST` with no data) got `411 Length Required` from body-size-limiter. Node handed the app an empty body instead of no body. In 0.1.2, these requests have `request.body === null`, the same as on Bun, so they pass the limiter. Requests with a body are unchanged.

## Other fixes

- `start` warns when the build is older than any file in `src/`, `ecosystem/` or `burger.build.ts`. Before, it only looked at `src/`.
- `dev` restarts on changes in `ecosystem/` even when the folder was created after `dev` started, for example by `burger-api add` in another terminal.
